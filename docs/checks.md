# Checks

Generated by `tools/generate_checks_doc.py` from the check registry. Edit the
`rationale` on the check, not this file.

Every default severity below was set from how often the check fires on the
pinned public corpus of 3,799 Sigma rules, not from how serious the finding
sounds. A check that fails the build on a quarter of a team's existing rules is
a check that gets switched off in its first week, so a high firing rate argues
for a warning default even where the finding is worth making. The rates are
measured, and `benchmark/run_benchmark.py` reproduces them.

Two findings cannot be configured: a file that does not parse, and a file that
parses and is not a Sigma rule. Neither can be assessed, and neither will load
in a backend.

## attack-technique-missing

**rule has no ATT&CK technique tag**

A coverage review counts techniques. A rule tagged only with a tactic cannot be placed on a coverage matrix, cannot be compared against a threat profile, and cannot be found by anyone asking what detects a specific technique. Groups and software tags describe who, not what.

- Default severity: `warning`
- Scope: rule
- Fires on 470 of the corpus (12.37%)

## broad-logsource

**log source names a product with no category or service**

The backend evaluates the rule against every event the product emits rather than one event channel, which multiplies the cost of the rule by the size of the estate. Add the category or the service the detection was written against.

- Default severity: `warning`
- Scope: rule
- Fires on 19 of the corpus (0.5%)

## condition-undefined-selection

**condition names a selection the rule does not define**

A backend resolves the missing name to nothing, so the rule either matches everything or matches nothing depending on where the name sits in the condition. Neither failure announces itself: the rule deploys, runs, and is silently not the detection anyone reviewed.

- Default severity: `error`
- Scope: rule
- Fires on 0 of the corpus (0.0%)

## condition-unparseable

**condition cannot be read**

Either the condition is malformed, or it uses a form this tool does not implement. Both are worth stopping for: the first will not load in a backend, and the second means the checks that read the condition did not run on this rule, so the rule was not fully gated.

- Default severity: `error`
- Scope: rule
- Fires on 0 of the corpus (0.0%)

## duplicate-rule-id

**two rules share an id**

The id is what every downstream system uses to tell one rule from another, so a duplicate means one of the two is invisible to deduplication, to tracking, and to whichever system loads them in an order nobody controls.

- Default severity: `error`
- Scope: corpus
- Fires on 0 of the corpus (0.0%)

## duplicate-yaml-key

**the same key appears twice in one mapping**

The YAML parser keeps the last value and discards the earlier one in silence. If the repeated key is a selection, half the detection was lost before any check could see it, and the rule will behave as though the first block was never written.

- Default severity: `error`
- Scope: rule
- Fires on 0 of the corpus (0.0%)

## missing-falsepositives

**rule has no usable false positive note**

The note is the handover to whoever triages the alert. An empty field, or the word Unknown, tells them the author did not know either, which is the moment a real detection starts being closed as noise. Name one thing that legitimately fires this rule, or say explicitly that nothing is expected to.

- Default severity: `warning`
- Scope: rule
- Fires on 949 of the corpus (24.98%)
- Options: `levels` (default `['high', 'critical']`)

## missing-rule-id

**rule has no id**

Without a UUID the rule cannot be tracked across a rename, cited in a ticket, or matched against the upstream rule it came from. Generate one once and it never changes again.

- Default severity: `error`
- Scope: rule
- Fires on 0 of the corpus (0.0%)

## rule-invalid

**file is valid YAML but not a Sigma rule**

A required field is absent or has a value the specification does not allow. The rule will not load, so the remaining checks were not run against it.

- Default severity: `error`
- Scope: file

## suppression-unknown-check

**suppression names a check that does not exist**

The suppression applies to nothing, so the rule looks silenced and the gate still fires. A misspelled check id here is the quietest way to believe a finding was handled.

- Default severity: `error`
- Scope: file
- Fires on 0 of the corpus (0.0%)
- Not configurable

## suppression-without-reason

**suppression comment gives no reason**

Silencing a finding is a decision, and the person who benefits from it being written down is whoever reads the rule next year. Add 'reason: ' and a sentence after the check name.

- Default severity: `error`
- Scope: file
- Fires on 0 of the corpus (0.0%)
- Not configurable

## unbounded-selection

**selection matches every event in the log source**

Every constraint in this selection matches any value, and the condition makes the selection sufficient on its own, so the rule fires on everything the log source emits minus its filters. That may be deliberate for an allowlist style detection, in which case suppress it with the reason, so the next reviewer knows it was a decision.

- Default severity: `warning`
- Scope: rule
- Fires on 1 of the corpus (0.03%)

## unknown-field-modifier

**field uses a modifier the specification does not define**

A misspelled modifier does not fail. It converts, deploys, runs and matches nothing, while the rule still appears in the coverage report. Check the spelling against the Sigma modifier appendix, or add the name to extra_modifiers if your pipeline defines it.

- Default severity: `error`
- Scope: rule
- Fires on 0 of the corpus (0.0%)
- Options: `extra_modifiers` (default `[]`)

## Turning a check off

In `.detection-rule-gate.yml`:

```yaml
checks:
  missing-falsepositives: off
  attack-technique-missing: error
```

For one rule, in the rule file, with a reason that is not optional:

```yaml
# drg:ignore unbounded-selection reason: allowlist detection, breadth is the design
```
